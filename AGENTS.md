## What this repo is

**Buena Mono** — a writer-first monospace typeface, tuned for extended prose in
markdown and code editors while keeping code legible. Two-axis variable font:
weight 100–800, slant 0 to −10°, from 8 masters. 5,406 glyphs, 4,285
codepoints, 971 languages, 51 OpenType features. Ships under the OFL.

Source of truth for the faces themselves. The specimen site is
`buena-mono.buenalabs.io`; typeface *roles* across products are decided in
[`studio/decisions/brand-typeface-roles.md`](https://github.com/buenagames/studio/blob/main/decisions/brand-typeface-roles.md).

## Commands

Everything is `make`. `make help` lists targets; the ones that matter:

| | |
|---|---|
| `make build` / `build-all` | build the fonts; `build-otf`, `build-woff2` for one format |
| `make qa` / `qa-source` / `qa-all` | fontspector and source checks |
| `make proof` / `sprite-specimen` | visual proofs |
| `make check-manifest` | the manifest matches what was built |
| `make package` / `promote-fonts` | release artifacts |

Run `make qa` before proposing any outline change. A font that builds is not a
font that passes.

## What to be careful about

**Generated artifacts are not sources.** Anything under `fonts/` is built.
Editing it produces a change the next `make build` silently reverts.

**Interpolation is the failure mode.** A change that looks right at Regular can
go underweight at 800 or break compatibility between masters. `make qa` is how
that surfaces; a visual check of one weight is not.

## Org conventions

Defined once in [`buenagames/studio`](https://github.com/buenagames/studio).
Where this file and `studio` disagree, `studio` wins and this file is the bug.

**Commits.** `type(scope): description`, imperative, subject under 72
characters, no trailing period. Types: `feat` `fix` `docs` `style` `refactor`
`test` `chore` `ci` `build`.

**No AI-attribution trailer of any kind.** Not `Co-Authored-By`, not
`Generated-With`, not an equivalent under another name. The commit body ends at
its last content line. Issue trailers (`Refs`, `Fixes`) are unaffected --- they
describe the change, not who typed it.

**Stage by path.** Never `git add -A` or `git add .`; both sweep in whatever
else is dirty. Verify with `git diff --staged` before committing.

**One definition, in one place.** A rule that lives in three repos holds three
positions and nobody notices. Shared things get one owner and everything else
points at it.

**Say what shipped, not what is nearly done.** A claim is a promise with a
shorter deadline.
